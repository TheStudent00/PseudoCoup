GNU C's operators, sorted by their definitions in clang's code

Figure 1. The operators GNU C accepts and reads back as written: clang 21.1.8 judged each listed form and builtin as -std=gnu17 for riscv64 over 52 holders, and read each accepted one back through its syntax tree (runs elv2_l66 to elv2_l71). Colour says one thing: the sort, read from clang's lowering code compiled in debug mode (runs elv2_l65, elv2_l69). Complex: its definition reaches another operator's own function (a *= b hands on EmitMul). Basic: it reaches none. The centre is the whole; each ring outwards is one level down. Click a sector, and its notes are listed below the figure.

What it does not show. The holders each operator takes (mask/gnu17/summary.json), and the forms and builtins clang refused for every holder. Where the holder changes the answer (-a; the compound assignments on _Atomic holders), the operator's line says so.
