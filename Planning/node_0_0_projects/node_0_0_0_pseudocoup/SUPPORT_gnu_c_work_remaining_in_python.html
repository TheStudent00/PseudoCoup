GNU C work remaining

Figure 1. The list's problems, each marked once in one small program. It shows what the model captures, not how long each takes.

GNU C, written in Python's syntax. Holders are C's types under ctypes' names: c_int is int, c_char plain char, c_longdouble long double, POINTER(Point) a struct point *, byref(x) is &x. Operators keep C's meaning: / on two c_int is C's division. An import stands for an #include; libc is the C library, stdatomic is <stdatomic.h>. A comment after # says in plain words what its line does.

A mark is one problem. Click or tap it, or a line of the list on the right, for its card. Each problem is marked once; the same problem comes back unmarked elsewhere (every first assignment is a declaration, every literal a constant, every variable a name).

Colours: remains; done (some by hand now, maybe modelled later, at the owner's word); later, with our own optimizing of arch-opcodes; out: by the all-three-architectures rule, outside our configuration (GNU C, -O0 -g), clang's own gap, or closed as needing nothing more. The list shows what remains; its button shows the rest.

Unmarked code: HiOps that held_HiOp_wrapper held and map_HiOp_to_unit() lowered and cut, among the 321,882 that clang lowered for riscv64 (run elv2_l156).
